# 情報処理安全確保支援士 学習アプリ 開発依頼書

Claude Code向けの引き継ぎ資料です。`prototype/sc-study-app-prototype.html` はclaude.ai上で作った動作する試作品です。画面構成、問題データ、計画タスクはここから取り出して使ってください。

---

## 1. 目的

情報処理安全確保支援士試験（SC）に合格するための個人用アプリを作る。

- **管理**：試験までの残り日数、学習時間の記録、計画タスクの進捗、テーマ別の正答率を1画面で把握する
- **学習**：一問一答で知識を定着させ、苦手な問題を優先して出題する

利用者は1人（本人のみ）。スマホとPCの両方から使い、同じデータを見られることが必須。

## 2. 利用者について

- 中小企業向けITサポートのエンジニア（Microsoft 365（マイクロソフト365）運用、ネットワーク構築、PCキッティングが主業務）
- 通勤は車（7:00〜8:30の間で日によって変動）。通勤中は画面を見られないため、音声での復習手段があると理想
- 平日の夜60〜90分、休日3時間の学習を想定
- 過去にReactでの学習ゲームやNext.jsのシステムを作った経験あり

## 4. 学習方針（アプリに反映する計画）

前期でA-1通過を最優先にし、後期で合格を取りにいく2段構え。

| フェーズ | 期間 | 内容 |
|---|---|---|
| 1 | 9/29〜10/26 | 科目A集中。A-1を1日30問、A-2を1日20問。第3週から年度別の通し演習 |
| 2 | 10/27〜11/21頃 | 科目B初挑戦。令和7→6→5年度の順に、時間無制限→制限時間つき→150分通し |
| 3 | 11/22〜2027/1/26 | 重点テーマを1週1テーマで体系インプット。科目Bを平日1問、休日2問 |
| 4 | 1/27〜3/28 | 後期申込（A-1免除申請）。A-2と科目Bの全年度演習 |

週ごとのタスク31件は、試作品の `TASKS` 配列にある（ID `t01`〜`t31`）。

重点テーマ：認証・認可 / 暗号・PKI / メール・DNS / Webアプリ / ネットワーク / クラウド・監視 / インシデント対応 / サプライチェーン / マネジメント・法令 / A-1共通知識

## 5. 機能要件

### 5.1 管理

- **残り日数**：前期A、前期B、後期A-2、後期Bの4つ。直近の試験を強調
- **今週の学習時間**：月曜始まり。科目別の積み上げバーと、週目標（初期値600分、変更可）に対する達成率
- **記録**
  - タイマー：科目を選んで開始→終了で自動記録。1分未満は記録しない。リロードしても計測が続くこと
  - 手入力：日付、科目、分（1〜600）、メモ（120文字まで）
  - 科目：科目A-1 / 科目A-2 / 科目B / インプット / 一問一答
- **直近14日のグラフ**：日別、科目別の積み上げ棒グラフ。今日を強調
- **計画タスク**：週ごとにまとめ、今日を含む週を開いた状態で表示。チェックで完了
- **テーマ別の正答率**：一問一答の結果から集計。60%未満を警告色で表示
- **学習ログ一覧**：新しい順。削除は2段階確認

### 5.2 学習（一問一答）

- 4択。選択肢の並び順は毎回シャッフル（正解位置を覚えないように）
- 回答後に正誤と解説を表示
- 出題順：「苦手・未回答を優先」と「ランダム」
  - 苦手度＝不正解数÷回答数。未回答は最優先。最終回答から3日以上経った問題は少し優先度を上げる
- テーマで絞り込み、問題数は5/10/20から選択
- 終了時に正答数、正答率、間違えた問題の一覧を表示。所要時間を学習ログに記録するボタン
- 問題は試作品の `Q` 配列にある52問（すべてオリジナル）。`questions.json` などに切り出して管理する

### 5.3 あると良い機能（優先度順）

1. 問題の追加・編集画面（テーマ、問題文、選択肢4つ、正解、解説）
2. 間違えた問題だけを復習するモード
3. 通勤用の音声モード：問題と解説を読み上げる（Web Speech APIなど）。運転中の操作は不要な設計にする
4. 用語カード（暗記用、表と裏）
5. 科目Bの演習記録（年度、問番号、得点、所要時間、振り返りメモ）
6. データのエクスポート（JSON/CSV）

## 6. データモデル（試作品での構造）

```
logs/{id}        { date: "YYYY-MM-DD", minutes: number, subject: "A1"|"A2"|"B"|"IN"|"QZ", memo: string, createdAt: number }
plan/checks      { t01: boolean, t02: boolean, ... }
quiz/stats       { [questionId]: { c: 正解数, w: 不正解数, last: 最終回答のUnix ms } }
settings/main    { goal: number(分/週), examA: "YYYY-MM-DD", examB: "YYYY-MM-DD" }
```

問題データ：

```
{ id: "au1", t: "auth", q: "問題文", c: ["選択肢1","選択肢2","選択肢3","選択肢4"], a: 正解のindex, e: "解説" }
```

テーマキー：`auth` `crypto` `mail` `web` `net` `cloud` `ir` `supply` `law` `a1`

## 7. 技術面（未決定。提案を求めたい点）

- **構成**：スマホで使うのでPWA化を希望。候補はNext.jsまたはVite＋React
- **データ同期**：スマホとPCで同じデータを使う必要がある。候補はSupabase、Firebaseなど。オフライン時も記録でき、復帰時に同期できると望ましい
- **認証**：本人のみ使用。シンプルな方式でよい
- **ホスティング**：Vercelなど無料枠で運用できるもの
